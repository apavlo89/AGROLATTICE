IMPLEMENTATION SCOPE
--------------------
11.15 rebuilds Reports as a persistent scientific-reporting and publication workspace rather than a session-state/project export page.
Major implemented capabilities include:
- true lazy Reports Command Centre with Overview, Report Builder, Publications, Tables & Figures, Evidence & Claims, Reproducibility, and Report Library;
- persistent report scope using portfolio/field/trial/Twin/model-linked evidence;
- purpose-built report templates for experiments, maize synchrony, Persistent Twin seasons, field seasons, climate/EO, crop decisions, model validation, recommendation/outcome audit, G×E×M, manuscripts and supplementary/reproducibility packages;
- direct persistent evidence collection from Field Operations, Experiments, Persistent Twin and Research Evidence rather than requiring CSV re-upload or current Streamlit session objects;
- report data-readiness checks and explicit preliminary/incomplete-evidence warnings;
- immutable evidence snapshots and immutable report versions;
- persistent report/study registry, report artifact registry, claim ledger, citation library, export history and audit trail;
- structured manuscript metadata, authors/affiliations/ORCID, structured abstract, generic manuscript presets, funding/conflicts/ethics/data/code availability and section word counts;
- modern global methods registry with native/paper-derived/external/legacy relationship labels and source references;
- publication-quality table controls and standard scientific table shortcuts;
- expanded scientific figure builder including intervals, calibration, ROC/PR, residuals, observed-vs-predicted, confusion matrices, PCA/climate space and spatial points;
- PNG 300/600-dpi and true SVG figure export, underlying CSV and figure-generation manifests;
- multi-panel figure assembly;
- Results Builder for evidence-grounded descriptive result blocks;
- Claim Ledger with evidence type, source/statistic linkage and scientific-wording audit;
- report audit for placeholders, unsupported/high-risk claim language, citation gaps, evidence readiness and selective-reporting warnings;
- limitation suggestions derived from actual evidence/readiness and model information;
- researcher-friendly Evidence & Claims view plus advanced raw provenance on request;
- rich reproducibility manifests containing database/model/dataset/report evidence identifiers where available;
- one-click manuscript/reproducibility ZIP generation with Markdown, HTML, DOCX, tables, figures, citations, claims, audit and README;
- Internal versus Public package privacy profiles with explicit heuristic redaction controls and warnings;
- persistent report version/export history;
- optional AI-assisted reporting audit constrained to frozen AGROLATTICE evidence and explicitly prohibited from inventing measurements, significance, causal effects or references;
- legacy Release-3 publication/workflow utilities retained under All Tools / Legacy instead of remaining the primary Reports interface;
- climate-centric Statistics and Scientific Robustness tools recategorised outside the primary Reports workflow;
- retention of k=2..20 PCA/K-means climate exploration introduced in 11.13.

SCIENTIFIC-INTEGRITY GUARDS
---------------------------
- Reports are built from selected/frozen evidence rather than silently generating new scientific results.
- Frozen evidence snapshots retain source/provenance manifests and checksums where available.
- Report versions are immutable; revised manuscripts become new versions.
- High-risk wording such as caused, improved, optimal, validated, significant, generalizable and guaranteed is surfaced for review when claim evidence may not support it.
- AI-assisted reporting is optional and is instructed not to invent measurements, significance, causal effects or references.
- Built-in paper-derived methods explicitly record whether AGROLATTICE is a native method, independent adaptation, external implementation or legacy approximation where known.
- Public-package redaction is explicitly heuristic and is not represented as guaranteed anonymisation.
- Missing/incomplete outcomes and validation evidence remain visible in report readiness and audit outputs.
- Saving a report or evidence snapshot does not upgrade the validation/causal status of the underlying evidence.

PERFORMANCE
-----------
The primary Reports workspace uses true lazy navigation and contains no top-level eager st.tabs().
Opening Reports reads lightweight persisted summaries only.
Full artifact loading, figure generation, evidence freezing, report audit and publication-package assembly occur only after explicit researcher actions.
NASA/STAC retrieval, model fitting, EO processing and crop-model execution are never triggered merely by entering Reports.

KNOWN LIMITATIONS / DELIBERATE SAFEGUARDS
-----------------------------------------
1. A full interactive Streamlit browser session could not be run in this packaging environment because Streamlit is not installed here. RUN_APP.bat performs the target-environment preflight on Windows/Anaconda.
2. Public-package redaction uses explicit column-name/text heuristics. Researchers must review exported files before public release; 11.15 does not claim automatic de-identification is complete.
3. Generic manuscript presets are provided; current journal-specific submission rules are not invented or assumed. Researchers should configure/verify target-journal requirements independently.
4. The Results Builder produces evidence-grounded descriptive result blocks. It does not infer causal conclusions or statistical significance that are absent from source analyses.
5. Automatic method inference depends on persisted evidence/model metadata. Researchers must review the final Methods text and citations.
6. Restricted/proprietary data are not automatically bundled into public reproducibility packages; manifests and access information can be included instead.
7. Legacy publication/project workflows are retained only for backward compatibility under All Tools / Legacy and may still use session-state-oriented behavior.
8. Citation records are only as complete as the stored bibliographic metadata. The application does not fabricate missing reference details.
